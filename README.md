# Project G Launcher

Отдельный Windows-first лаунчер на .NET 10 / Avalonia. Репозиторий игры ему не нужен.

## Запуск

```powershell
dotnet build Launcher.slnx
dotnet test tests/Launcher.Tests/Launcher.Tests.csproj
dotnet run --project src/Launcher.App
```

Откройте «Настройки»: HTTPS-адрес `manifest.json`, **открытый** ключ издателя в PEM, абсолютная папка игры и адрес/UDP-порт сервера. Настройки сохраняются в `%LOCALAPPDATA%/ProjectG/Launcher/settings.json`. Папка игры по умолчанию — `%LOCALAPPDATA%/ProjectG/Game`.

При первом запуске можно положить `launcher.settings.json` рядом с EXE для предварительной настройки распространённого лаунчера. Формат ниже; замените значения своими. Локальные сохранённые настройки имеют приоритет. Открытый ключ поставляется с доверенной копией лаунчера, его нельзя автоматически получать с сервера обновлений.

```json
{
  "manifestUrl": "https://updates.example.com/project-g/manifest.json",
  "publicKeyPem": "-----BEGIN PUBLIC KEY-----\n...\n-----END PUBLIC KEY-----",
  "installDirectory": "D:\\Games\\ProjectG",
  "serverHost": "game.example.com",
  "serverPort": 9050
}
```

Лаунчер проверяет обновления при открытии. «Играть» повторно проверяет релиз, при необходимости устанавливает его, проверяет файлы и запускает клиент. «Установить / обновить» позволяет установить или восстановить игру без запуска. «Предыдущая версия» возвращает предыдущую полностью проверенную сборку; последующее нажатие «Играть» снова применит релиз, который опубликован в манифесте. Для общего отката издателю нужно опубликовать манифест нужной сборки.

## Подготовка релиза

Экспортируйте **полную Windows .NET-сборку Godot**, включая DLL/runtime и ресурсы, в отдельную папку. Лаунчер не экспортирует Godot-проект самостоятельно.

Один раз создайте ключ издателя. Храните его в закрытом каталоге с ограниченным доступом; команда не шифрует PEM. Не включайте закрытый ключ в Git, ZIP, GitHub Releases или настройки игроков.

```powershell
dotnet run --project tools/ReleaseTool -- keygen .keys
```

Пример упаковки (версия и протокол должны соответствовать реальной сборке; `27` — пример, не автоматически определённое значение):

```powershell
dotnet run --project tools/ReleaseTool -- pack D:\exports\ProjectG releases\0.1.0 0.1.0 27 ProjectG.exe https://updates.example.com/project-g/0.1.0/client.zip .keys\release.private.pem
```

Получатся `client.zip`, `manifest.json` и бинарный `manifest.json.sig`. Сначала опубликуйте архив по неизменяемому версионному URL, затем манифест и подпись. `.sig` располагается рядом с манифестом: `manifest.json.sig`. Упаковщик ничего не публикует и не перезаписывает существующие результаты. GitHub Releases или другое HTTPS-хранилище настраиваются отдельно. Адреса example.com в примерах не рабочие.

Подпись — ECDSA P-256 / SHA-256, формат IEEE P1363 (64 байта), над точными UTF-8 байтами JSON. После подписания нельзя переформатировать JSON. Манифест schema 1 содержит version, protocol, downloadUrl, sha256, size и executable. Поле protocol информационное: окончательную совместимость проверяет игровой handshake.

## Поставка лаунчера

```powershell
dotnet publish src/Launcher.App -c Release -r win-x64 --self-contained true -o .artifacts\launcher-win-x64
```

Если системный диск заполнен, используйте `pwsh -File tools/Publish-Windows.ps1`: кэш и временные файлы этой сборки будут находиться в `.artifacts` на диске репозитория.

Передайте игрокам **всю папку** публикации вместе с доверенными настройками. Им не потребуется установленный SDK. Это portable-приложение, без установщика и самообновления лаунчера. Windows Authenticode-подпись EXE здесь не настроена; она отличается от подписи игровых обновлений.

## Устройство обновления

- `Launcher.Core`: подпись, HTTPS, скачивание, ZIP, верификация и управление установками; без зависимости от UI.
- `Launcher.App`: Avalonia UI; прогресс, отмена, настройки, запуск.
- `ReleaseTool`: упаковка и подпись готового экспорта.
- `Launcher.Tests`: проверки с поддельным HTTPS handler и изолированными временными папками.

Установка использует `staging/<uuid>` и `versions/<uuid>/game`. Архив проверяется до распаковки. `install.json` хранит контрольные суммы каждого установленного файла. После завершения единственный указатель `current.json` атомарно переключается на новую сборку. Предыдущая папка не изменяется. Прерывание до переключения сохраняет старую выбранную версию. При аварийном завершении могут остаться неиспользуемые staging/version-каталоги: автоматическая очистка старых сборок пока не реализована. Место требуется под текущую игру, архив и распакованную новую версию.

ZIP ограничен 8 ГБ, распаковка — 20 ГБ и 50 000 entries. Отклоняются traversal, абсолютные пути, альтернативные NTFS streams, специальные имена Windows, ссылки и совпадающие без учёта регистра пути. HTTPS-перенаправления повторно проверяются. Скачивание имеет предел времени и размера. Одновременные операции блокируются файловым lock. Перед запуском проверяется каждый файл; игра должна писать сохранения/логи в Godot `user://`, а не в папку установленной сборки.

Лаунчер остаётся открытым во время игры и держит lock; его можно свернуть. Закрытие во время загрузки отменяет операцию, после чего окно можно закрыть повторно. Старые версии не удаляются, пользовательские сохранения не затрагиваются. Установку в каталог с junction/symlink нельзя использовать. От атак уже запущенного под той же учётной записью локального ПО эта схема не защищает.

## Граница с Project G

Клиент запускается с аргументами `-- --server-host=<host> --server-port=<port>`.
На момент создания лаунчера текущий `Content.Client/Scripts/Network/NetworkClient.cs` поддерживает только `--server-port` и всё ещё подключается к `127.0.0.1`. Чтобы выбранный адрес работал, в **репозитории игры** нужно добавить обработку `--server-host`. Лаунчер не снимает localhost-ограничение Development identity. Доступ друзей на VPS потребует отдельного защищённого входа. Исходники игры этой задачей не изменяются.

Производственный endpoint, подписанная реальная сборка и ключ издателя в репозиторий не включены. Первое окно честно просит настройки, не показывает выдуманный статус игрового сервера.

Документация Avalonia: https://docs.avaloniaui.net/docs/fundamentals/application-lifetimes
